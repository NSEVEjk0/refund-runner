# Refund Runner

Build a useful consumer caseworker for refunds a merchant has already promised. Keep the first workflow narrow and verifiable. Voice is turn-based intake, explanation and an explicitly labelled practice support desk. No telephony provider or real merchant messaging is connected.

Never describe a practice settlement as money recovered. Never infer legal eligibility, a missing refund outside the supplied statement, or authenticity of a customer-uploaded document. Handle paid, partial, pending and ambiguous credits explicitly. Customer-reviewed facts, source citations and computed results are separate concepts.

All file decoding and model-written Python execute out of process in the pinned gVisor runtime, with no network, credentials or host interpreter fallback. The fixed verifier lives outside the candidate interpreter. Preserve read-only inputs, actual Docker policy inspection, resource bounds and confirmed teardown. Sandbox names and cleanup labels belong exclusively to Refund Runner.

The controller alone calls Vultr Serverless Inference. Explain this data transfer before a customer's first upload/recording. Never let generated text, an audio transcript, a merchant message, or a spoken yes approve a settlement. Bind the explicit approval to the exact case, mandate, transcript and terms.

Preserve existing sites and services. Run meaningful financial, approval, containment, live-provider and browser checks. Test microphone handling, actual audio/video playback, mobile layout and downloads. Label synthetic fixtures, simulation, real inference and measured tests accurately. Never invent revenue, users, outcomes or winning prospects.

Keep credentials, private case state and raw recordings out of git and public bundles. No third-party communications without explicit authorization. The user has authorized building, testing and deployment of this project; do not ask for the same permission again.
